Chapter 01

What is ns-3?

ns-3 is a free, open-source, discrete-event network simulator built for Internet research and education. Think of it as a virtual lab where you write C++ (or Python) code to describe a network and run experiments — no physical hardware needed.

Core idea

Every network event — a packet being sent, a queue filling up, a link failing — is a C++ function call scheduled in time. The simulator fires these events in chronological order. No real time passes; the clock only advances when an event fires.

Key tags:
Discrete-event Internet systems Open-source C++ + Python
Why use it?
  • Study networks that are too expensive or dangerous to build physically
  • Run experiments in a controlled, reproducible environment
  • Execute real implementation code inside the simulator
  • Freely extensible — add your own protocols, devices, models
  • Actively maintained with regular releases
ns-3 vs ns-2 — what changed?
Feature ns-2 ns-3 ✓
Scripting OTcl + C++ C++ or Python
Run from C++ Not possible Yes — just a main()
Real code emulation No Yes
Multiple NICs per node Limited/buggy Full support
Trace output nam animator pcap, ASCII, NetAnim, Gnuplot
Maintenance Lightly maintained Active — 3.47 Feb 2026

Chapter 02

Core abstractions

ns-3 is built around five key abstractions. Everything in a simulation is one of these things, or attached to one of them. Click each layer to expand details.

📦
Application
Generates or consumes traffic
top
Like user programs on a real OS — but there's no actual OS in ns-3. Apps run on Nodes and drive simulation activity. Built-in examples: UdpEchoClient, UdpEchoServer, OnOffApplication, BulkSendApplication. You schedule start/stop times with app.Start(Seconds(2.0)).
🔗
Internet stack
TCP, UDP, IPv4/v6, ARP
protocols
The full TCP/IP stack. Install it on nodes with InternetStackHelper. Protocols talk through the TrafficControlLayer, which enforces queueing discipline before handing packets to the NetDevice. Supports TCP variants: Reno, NewReno, CUBIC, BBR.
💻
NetDevice
Simulated NIC — driver + hardware
device
Models both the software driver and the NIC hardware together. A Node can have multiple NetDevices (multiple network interfaces). Types: PointToPointNetDevice, CsmaNetDevice, WifiNetDevice. Each pairs with its matching Channel type only.
〰️
Channel
The medium — wire, wifi spectrum
medium
The medium packets propagate through. PointToPointChannel connects exactly 2 devices, models a dedicated cable with configurable delay. CsmaChannel is a shared bus (like classic Ethernet). WifiChannel uses the YansWifiChannel propagation model.
⬡
Node
The simulation host — like a computer
base
The fundamental unit. A Node holds NetDevices, protocol stacks, and Applications. Think of it as a graph node (from Graph Theory) — not a "host" (to avoid Internet-specific connotations). Created with NodeContainer nodes; nodes.Create(2);. Everything is attached to a Node or to something on a Node.
Packet flow through layers
Attribute system

Every ns-3 model object exposes typed key-value attributes you can read and write. This is how you configure parameters without recompiling.

// Set via helper
p2p.SetDeviceAttribute("DataRate", StringValue("5Mbps"));

// Set via global config path
Config::Set("/NodeList/0/DeviceList/0/TxQueue/MaxSize",
            StringValue("25p"));

// Wildcard — affects ALL nodes
Config::Set("/NodeList/*/DeviceList/*/TxQueue/MaxSize",
            StringValue("15p"));
Chapter 03

Getting started

ns-3 is distributed as source code. You compile it yourself. Here's the complete workflow from zero to running your first simulation.

Prerequisites
C++ compiler g++ ≥ 9 clang++
Python ≥ 3.8
CMake ≥ 3.13
Build system make / ninja
Platform Linux macOS WSL2
Check versions:
python --version   # need 3.8+
g++ -v             # need 9+
cmake --version    # need 3.13+
⚠ Windows users

Native Windows Visual Studio is not currently supported. Use one of these instead:

  • WSL2 with Ubuntu — recommended, full support
  • Docker container with Ubuntu image
  • Msys2 + MinGW64 — supported since ns-3.37
  • Linux virtual machine
Complete installation walkthrough
1
Download ns-3
Two options — tarball release (simpler) or Git clone (gets latest dev): 
# Option A — tarball (recommended for beginners)
mkdir workspace && cd workspace
wget https://www.nsnam.org/release/ns-3.45.tar.bz2
tar xjf ns-3.45.tar.bz2
cd ns-3.45

# Option B — Git (gets development tree)
git clone https://gitlab.com/nsnam/ns-3-dev.git
cd ns-3-dev
2
Configure the build
ns-3 wraps CMake with a Python script called ./ns3. The two most common build profiles are debug (with assertions, slower) and optimized (faster, for big simulations):
# Optimized build with examples + tests enabled
./ns3 configure --build-profile=optimized \
                --enable-examples --enable-tests

# Debug build (default, good for development)
./ns3 configure --enable-examples --enable-tests
3
Compile
This compiles all ns-3 libraries into the build/ directory. First compile takes several minutes.
./ns3 build
# Libraries appear in build/lib/
4
Run the test suite
Verify your build is correct. All tests should PASS or be SKIPped.
./test.py
# PASS: 1200+ unit tests
# Takes ~5-10 minutes
5
Run your first program
Execute the canonical first.cc example. The ns3 wrapper automatically adds shared library paths so ns-3 libraries are found.
./ns3 run first
# Output:
Sent 1024 bytes to 10.1.1.2
Received 1024 bytes from 10.1.1.1

# View all command-line options
./ns3 run 'first --PrintHelp'

Your own simulation scripts

Official example programs
build/
Compiled libraries & binaries
contrib/
Contributed third-party modules
Chapter 04

Your first ns-3 script

The canonical example examples/tutorial/first.cc creates two nodes connected by a point-to-point link, sends a UDP packet from node 0 to node 1, and prints the result. Here's what every line does.

What the simulation does (visual)
Annotated first.cc — full breakdown
① Includes & logging setup 
// ns-3 modules group related classes — include what you need
#include "ns3/core-module.h"       // Simulator, Time, logging
#include "ns3/network-module.h"    // Node, Packet, NetDevice
#include "ns3/internet-module.h"   // TCP/IP stack
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"

using namespace ns3;
// Declare a logging component for this file
NS_LOG_COMPONENT_DEFINE ("FirstScriptExample");
② Create nodes
// NodeContainer groups Node objects
NodeContainer nodes;
nodes.Create (2);  // Creates node 0 (client) and node 1 (server)
③ Configure the link
PointToPointHelper pointToPoint;
pointToPoint.SetDeviceAttribute  ("DataRate", StringValue ("5Mbps"));
pointToPoint.SetChannelAttribute ("Delay",    StringValue ("2ms"));

NetDeviceContainer devices;
devices = pointToPoint.Install (nodes);
// This creates 2 NetDevices + 1 Channel, wires them together
④ Install TCP/IP stack & assign addresses
InternetStackHelper stack;
stack.Install (nodes);  // Installs IPv4, TCP, UDP, ARP on both nodes

Ipv4AddressHelper address;
address.SetBase ("10.1.1.0", "255.255.255.0");
Ipv4InterfaceContainer interfaces = address.Assign (devices);
// Node 0: 10.1.1.1   Node 1: 10.1.1.2
⑤ Install applications 
// Server on node 1, listening on UDP port 9
UdpEchoServerHelper echoServer (9);
ApplicationContainer serverApps = echoServer.Install (nodes.Get (1));
serverApps.Start (Seconds (1.0));
serverApps.Stop  (Seconds (10.0));

// Client on node 0 — sends to node 1's IP on port 9
UdpEchoClientHelper echoClient (interfaces.GetAddress (1), 9);
echoClient.SetAttribute ("MaxPackets", UintegerValue (1));
echoClient.SetAttribute ("PacketSize", UintegerValue (1024));
ApplicationContainer clientApps = echoClient.Install (nodes.Get (0));
clientApps.Start (Seconds (2.0));
clientApps.Stop  (Seconds (10.0));
⑥ Run the simulation
Simulator::Run ();      // Starts the event loop, fires all scheduled events
Simulator::Destroy ();  // Releases memory
return 0;
Chapter 05

Building topologies

ns-3 supports three main link types. Helper classes abstract away the dozens of low-level operations needed to configure each one.

Point-to-point connects exactly two nodes with a dedicated link. It's the simplest topology and the one used in first.cc. Configure with PointToPointHelper — set DataRate on the NetDevice and Delay on the Channel.
// Point-to-point setup
PointToPointHelper p2p;
p2p.SetDeviceAttribute  ("DataRate", StringValue("5Mbps"));
p2p.SetChannelAttribute ("Delay",    StringValue("2ms"));
NetDeviceContainer devs = p2p.Install(nodes);
CSMA (Carrier Sense Multiple Access) models a classic Ethernet bus. All nodes share one channel — only one can transmit at a time; collisions are detected and handled. Used in second.cc. Combined with a P2P link to routers in mixed topologies.
// CSMA bus — many nodes share one channel
NodeContainer csmaNodes;
csmaNodes.Add(p2pNodes.Get(1));  // share a node with P2P
csmaNodes.Create(3);              // add 3 more

CsmaHelper csma;
csma.SetChannelAttribute("DataRate", StringValue("100Mbps"));
csma.SetChannelAttribute("Delay",    TimeValue(NanoSeconds(6560)));
NetDeviceContainer csmaDevs = csma.Install(csmaNodes);
WiFi topology uses 802.11 protocols. Stations (STA) connect to an Access Point (AP) which bridges to the wired network. Requires WifiHelper, YansWifiPhyHelper (physical layer), and WifiMacHelper (MAC layer). The YansWifiChannel models wireless propagation loss.
// WiFi infrastructure setup
WifiHelper wifi;
wifi.SetStandard(WIFI_STANDARD_80211n);

YansWifiPhyHelper phy;
YansWifiChannelHelper channel = YansWifiChannelHelper::Default();
phy.SetChannel(channel.Create());

WifiMacHelper mac;
// AP side
mac.SetType("ns3::ApWifiMac", "Ssid", SsidValue(ssid));
NetDeviceContainer apDevs = wifi.Install(phy, mac, apNode);
// Station side
mac.SetType("ns3::StaWifiMac", "Ssid", SsidValue(ssid));
NetDeviceContainer staDevs = wifi.Install(phy, mac, staNodes);
Topology helper classes
Groups
NodeContainer
Groups Node objects. Call .Create(n) to make n nodes, .Add(node) to include existing ones.
Devices
NetDeviceContainer
Returned by helper .Install(). Holds pointers to created NetDevices. Use .Get(i) to get individual devices.
Addresses
Ipv4AddressHelper
Assigns IP addresses from a subnet. Call .SetBase("10.1.1.0","255.255.255.0") then .Assign(devs).
Routing
Ipv4GlobalRoutingHelper
Populates routing tables automatically. Call ::PopulateRoutingTables() after configuring all subnets.
Mobility
MobilityHelper
Sets node positions and movement. Required for WiFi. Use SetPositionAllocator and SetMobilityModel.
Stack
InternetStackHelper
Installs TCP/IP protocol stack on nodes. Must be called before assigning IP addresses.
Chapter 06

Tracing & logging

The whole point of running a simulation is to get data out. ns-3 gives you three complementary output mechanisms — pick based on how much detail you need.

📋

Logging module

Console output during simulation. Controlled at runtime via environment variables. 6 severity levels. Only available in debug builds — not suitable for performance-critical measurements.

NS_LOG_COMPONENT_DEFINE("MyComp");
// In code:
NS_LOG_INFO("Simulation starting");
// At runtime:
export NS_LOG=MyComp=info
./ns3 run myscript
🦈

pcap tracing

Captures raw packet data in standard pcap format — the same format used by Wireshark and tcpdump. One file per node/device pair. Great for detailed packet-level inspection.

// Enable on all devices
p2p.EnablePcapAll("myfirst");
// Creates: myfirst-0-0.pcap
//          myfirst-1-0.pcap
// Open with: wireshark myfirst-0-0.pcap
📝

ASCII tracing

Human-readable event log written to a text file. Records: packet transmit (+), dequeue (-), drop (d), receive (r) with timestamps.

AsciiTraceHelper ascii;
p2p.EnableAsciiAll(
  ascii.CreateFileStream("myfirst.tr"));
// + = enqueue  - = dequeue
// r = receive  d = drop
Log severity levels — least to most verbose
ERRORFatal errors
WARNWarnings
DEBUGDebug info
INFOGeneral info
FUNCTIONFunction entry
LOGICAlgorithm steps
# Enable multiple components and levels at once
export NS_LOG=UdpEchoClientApplication=level_all:\
             UdpEchoServerApplication=level_all
./ns3 run first
Custom trace sinks — fine-grained observation

The most powerful approach: connect a C++ callback function directly to a specific trace source inside any ns-3 object. This fires your function whenever that exact event occurs — no extra I/O overhead.

// 1. Define a trace sink callback
static void
RxDrop(Ptr<const Packet> p) {
  NS_LOG_UNCOND("RxDrop at " << Simulator::Now().GetSeconds());
}

// 2. Connect to a trace source on a specific device
devices.Get(1)->TraceConnectWithoutContext(
  "PhyRxDrop", MakeCallback(&RxDrop));

// Now RxDrop() fires every time node 1's device drops a packet

Quick reference

The most commonly used helpers, classes, and commands — all in one place.

Common helper classes
Link
PointToPointHelper
Builds dedicated P2P links. Set DataRate on device, Delay on channel.
.Install(nodes)
Link
CsmaHelper
Builds shared Ethernet-like bus connections. All nodes share bandwidth.
.Install(csmaNodes)
WiFi
WifiHelper
Configures 802.11 standard (a/b/g/n/ac/ax). Pairs with Phy and Mac helpers.
.SetStandard()
Protocol
InternetStackHelper
Installs full TCP/IP protocol stack including IPv4, IPv6, TCP, UDP, ARP.
.Install(nodes)
Address
Ipv4AddressHelper
Assigns IP addresses from a subnet to a NetDeviceContainer.
.Assign(devs)
App
UdpEchoServerHelper
Simple UDP echo server on a given port. Returns ApplicationContainer.
.Install(node)
App
UdpEchoClientHelper
Sends UDP packets to a server address/port. Configure MaxPackets, PacketSize, Interval.
.Install(node)
Routing
Ipv4GlobalRoutingHelper
Auto-computes routing tables for the entire topology. Must call after all interfaces are configured.
::PopulateRoutingTables()
Trace
AsciiTraceHelper
Creates output streams for ASCII trace files. Pass to EnableAsciiAll().
.CreateFileStream()
Simulator control
Simulator::Run();           // Start event loop
Simulator::Stop(Seconds(10)); // Schedule a stop time
Simulator::Now();           // Get current sim time → Time object
Simulator::Schedule(        // Schedule a future event
  Seconds(5.0),
  &MyFunction, arg1);
Simulator::Destroy();       // Clean up — always call at end
